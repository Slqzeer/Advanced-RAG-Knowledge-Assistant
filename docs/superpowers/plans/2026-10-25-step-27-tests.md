# Step 27 — Tests

## Goal

Turn the existing test suite and benchmark history into two explicit local gates:

```console
uv run pytest
uv run pytest --cov=app --cov-branch
uv run python scripts/benchmark.py --label regression-candidate \
  --gate-against compress-embedding-d20 --no-save
```

Step 28 will run these gates in GitHub Actions. This step defines and proves them
without adding CI configuration early.

## Measured baseline

- The step-26 branch passes Ruff, formatting, strict mypy, and all 643 non-paid tests.
- The suite measures 96% branch coverage over `app`; a 95% floor catches erosion
  without adding tests whose only purpose is to reach 100%.
- The shipped retrieval/compression row is `compress-embedding-d20`: Recall@5
  0.768, Recall@10 0.805, Recall@20 0.814, and MRR 0.810 over 45 questions.

## Contract

- Keep a plain `pytest` run free of paid API calls.
- Measure branch coverage over application code, not command wrappers, and fail
  below 95%.
- Compare a fresh benchmark with a named recorded baseline.
- Reject retrieval failures, changed fixture counts, missing metrics or categories,
  aggregate losses greater than 0.02, and per-category Recall@5 losses greater
  than 0.05.
- Return a non-zero process status when the regression gate fails.

## Execution

1. Add `pytest-cov` as the only new development dependency and configure the
   measured 95% application floor.
2. Test the regression verdict first: pass, aggregate loss, category loss,
   retrieval failure, and fixture drift.
3. Add the verdict to `app.evaluation.regression` and expose it through
   `scripts/benchmark.py --gate-against`.
4. Run the coverage gate and a real benchmark against the shipped baseline.
5. Re-run Ruff, formatting, strict mypy, and pytest; publish the evidence in the
   README and roadmap.

## Explicitly deferred

- GitHub Actions, service containers, cache keys, and badges: step 28 owns CI/CD.
- Paid generation and RAGAS judge gates: deterministic retrieval metrics are the
  regression signal available without spending money or inheriting judge noise.
- A 100% coverage target: the remaining branches are mostly process entry points
  and defensive failures; the measured 95% floor protects the tested application.
