# Step 28 — CI/CD

## Goal

Run step 27's two local gates in GitHub Actions without adding a deployment:

```text
pull request / push -> lint + format + types + 95% branch coverage
push to main / manual -> pinned corpus + Qdrant + retrieval regression gate
```

## Measured starting point

- `main` is clean at `7071896` and has no Actions workflow, repository variables,
  or Actions secrets.
- Ruff, formatting, and strict mypy pass locally.
- The coverage gate selects 648 non-paid tests and passes at 96.06% branch
  coverage. The first local run failed only because the execution sandbox denied
  pytest's user temp directory; a repository-local `--basetemp` reproduced the
  published green result.
- The recorded regression baseline uses 155 FastAPI Markdown files. The local
  corpus is byte-for-byte identical to FastAPI commit
  `50113da16fec53b66b80d75e80a89296de4fa5a5`; fetching FastAPI's moving default
  branch now returns 156 files, so an unpinned CI fetch is not a regression test.
- A fresh regression run needs an embedding-provider key. No Actions secret is
  configured yet, so the workflow can be implemented and checked locally but the
  remote regression job cannot be green until `OPENAI_API_KEY` is added.

## Contract

- Run the free quality job on every pull request and every push to `main`.
- Use Python 3.12, the locked dependency graph, the project's pinned uv version,
  and immutable commit SHAs for third-party actions.
- Give `GITHUB_TOKEN` read-only repository contents permission.
- Start the pinned Qdrant and Redis images with health checks so integration tests
  run rather than silently skip.
- Run the 95% branch-coverage gate once; do not duplicate it with plain pytest.
- Run the paid embedding/regression job only after the quality job and never on a
  pull request. Fail clearly when `OPENAI_API_KEY` is absent.
- Pin the source corpus revision before making the existing regression baseline a
  required CI signal.
- Cache uv downloads and the SQLite embedding cache; never cache Qdrant state or
  write a benchmark row from CI.

## Execution

1. Test and add a pinned revision to each corpus source; fetch that exact commit.
2. Add `.github/workflows/ci.yml` with a free quality job and a main/manual
   regression job using service containers.
3. Run the local lint, format, type, coverage, and fetch-script tests.
4. Add `OPENAI_API_KEY` as an Actions secret, push the workflow, and record one
   green Actions run before marking the step complete.
5. Update the README and roadmap with the measured Actions result, not a projected
   duration or status.

## Explicitly deferred

- Deployment and releases: the original step only asks for CI/CD as a green
  validation pipeline, and there is no deployment target.
- Paid generation and RAGAS jobs: step 27 deliberately chose deterministic
  retrieval as the regression signal.
- A badge before the first green remote run: step 30 owns the professional README,
  and a badge without evidence would misstate the current status.
